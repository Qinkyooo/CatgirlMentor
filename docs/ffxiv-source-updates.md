# FF14 数据源更新与自动恢复

工具按实际使用的数据字段验证兼容性，不以网站发布日期、构建哈希或数据版本变化作为拒绝查询的理由。下面的策略适用于源码与 Windows 安装版；不依赖模型生成或执行修复代码。

| 工具 / 数据源 | 自动适配与更新 | 不能安全适配时 |
| --- | --- | --- |
| 物品资料、配方、采集来源 / FFCafe | 接受新 schema 标识、数据版本和额外字段；逐项验证物品 ID、名称、关联字段和结果类型，返回实际数据版本 | 畸形响应不会伪装成物品不存在；资料查询可尝试百科备用来源 |
| 市场行情 / FFCafe + Universalis | 自动使用最新物品数据；行情按所需字段解析，无网站版本绑定；价格缓存 1–2 分钟 | 字段不兼容与网络失败分别报告，不把格式变化解释为稍后重试即可恢复；不编造价格 |
| 钓鱼、鱼窗、天气 / 鱼糕 | 发现首页当前模块和数据清单，按字段结构识别压缩变量；版本标签缺失时按脚本内容识别；缓存到期重新拉取数据，以内容摘要区分快照，因此不修改版本号的数据更新也能生效；攻略跟随当前清单与更新时间 | 新数据验证通过后才切换；鱼窗和天气可使用明确标注过期的上次有效快照；鱼种详情仍要求当前资料，避免把过期资料当作当前攻略 |
| 房区 / 房屋网站 | 自动发现当前页面脚本，不依赖脚本哈希或变量名；展示元数据每 5 分钟刷新；房源响应按字段和服务器 ID 验证；网络失败可使用已配置的镜像来源 | 抽签阶段含义、地区映射等无法验证时停止解释，避免错报房源或购买资格；不把旧房源当实时房源 |
| 攻略百科 / 灰机与 Console Wiki | 网页及 API 按内容解析；缓存一天后自动更新，支持 ETag；主来源失败尝试备用来源 | 备用来源也失败时，可返回带过期标记的缓存 |
| 工具名录 / 水晶驿站 | 按类别、链接、名称、说明识别条目，不依赖 CSS 类名；缓存一天后更新 | 可返回带过期标记的已验证名录 |
| PvP 轮换 | 配置 `tools.games.pvpRulesUrl` 后，每 30 分钟重新检查；远端规则的字段、地图名称、时长及自身摘要验证通过后自动采用新规则，不再因与内置规则不同而报错 | 网络失败使用本次运行中上次有效规则并标注过期；没有远端 URL 时仍使用内置或自定义离线规则，无法主动获知游戏改版 |

所有联网工具共用受保护的 HTTP 客户端。连接超时、断开及 HTTP 502/503/504 最多自动重试一次；请求仍受域名白名单、SSRF、重定向次数、响应大小和超时限制。

“自动适配”覆盖字段兼容的数据更新、额外字段、构建文件名与变量名变化，以及已知清单结构的更新。接口完全更换、字段含义改变、网站登录限制或数据源停止服务，不能保证自动修复。此时工具保留明确的失败或过期标记，不猜测数据含义。包内离线攻略库仍随发行版更新，不从网页自动重建。

## 回归与发布验证

```powershell
.venv/Scripts/python.exe -X utf8 -m pytest tests/test_ffxiv_compatible_updates.py tests/test_ffxiv_source_updates.py tests/test_market_fuzzy.py tests/test_pvp_rules.py tests/test_knowledge_deployment.py tests/test_knowledge_legacy_fallback.py -q
.venv/Scripts/python.exe -X utf8 scripts/smoke_ffxiv.py --live
```

发布前再用安装包内的 `CatgirlMentor/runtime/python.exe` 运行同一个 `scripts/smoke_ffxiv.py --live`，覆盖物品价格、物品资料、攻略与名录、PvP、钓鱼、天气和房区。实测脚本使用临时数据目录，不读取用户配置或调用模型。
